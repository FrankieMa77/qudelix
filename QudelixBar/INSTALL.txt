Qudelix for macOS 1.4.6
=======================
An unofficial menu bar app for configuring the Qudelix 5K over USB or
Bluetooth.
Not affiliated with or endorsed by Qudelix, Inc.


INSTALL - two clicks
--------------------
1. Double-click "Install Qudelix".

2. The FIRST time, macOS refuses to open it, saying it cannot verify the
   developer. That is expected, and it happens to every downloaded app that
   is not notarized through Apple: this one is signed only ad-hoc, not with
   a paid Apple Developer ID. Click Done, then open System Settings >
   Privacy & Security, scroll to the Security section, and click "Open
   Anyway" next to the message about Install Qudelix. Confirm once.

3. The installer copies Qudelix.app into Applications, replacing any copy
   already there, clears the download flag, and launches it. Look for the
   headphones icon in the menu bar - the app has no Dock icon and no window.

That "Open Anyway" trip is asked once, for the installer only. Because the
installer clears the download flag on the copy it makes, Qudelix itself never
shows that dialog.


ALTERNATIVE - one line in Terminal
----------------------------------
Open Terminal (Cmd-Space, type Terminal), paste this whole line, press Return:

rm -rf /Applications/Qudelix.app && cp -R /Volumes/Qudelix/Qudelix.app /Applications/ && xattr -dr com.apple.quarantine /Applications/Qudelix.app && open /Applications/Qudelix.app

It does exactly what the installer does, and skips the "Open Anyway" trip
entirely because the download flag is cleared before the app is first opened.


ALTERNATIVE - drag and drop
---------------------------
Drag Qudelix.app onto the Applications folder in this window and launch it from
there. Done this way the download flag stays on, so macOS refuses the first
launch and you take the same "Open Anyway" trip described above, for Qudelix
itself rather than for the installer.


VERIFYING THIS DOWNLOAD
-----------------------
Because the app is signed ad-hoc, macOS cannot tell you who built it, so the
"Open Anyway" click above is pure trust. Every release publishes a SHA-256 for
the DMG. Check the file you downloaded against it:

   shasum -a 256 /path/to/Qudelix-1.4.6.dmg

Compare that string to the one in the release notes; they must match exactly.
If a Qudelix-1.4.6.dmg.sha256 file came with the download, this does the same
comparison for you and prints "OK":

   cd ~/Downloads && shasum -a 256 -c Qudelix-1.4.6.dmg.sha256

Reading this from inside the mounted DMG? Then the hash is deliberately not
here — it lives on the release page, because a checksum shipped inside the file
it describes proves nothing.

The full source is published alongside, so you can also build it yourself and
skip the question entirely.


USING IT
--------
Connect the 5K by USB, or just have it powered on nearby for Bluetooth. The app
connects on its own and prefers USB when both are available; the menu bar icon
fills in when it is talking to the device. Click it for:

  - Live status: battery, charging, firmware, sample rate, input source
  - Volume slider and mute, USB sample rate control
  - EQ on/off and the 20 preset slots, which you can name from the app
  - A 10- or 20-band parametric EQ editor: drag the curve, click a band to
    inspect it, undo, per-band mute, auto pre-gain, save-to-preset
  - A preset library on the Mac beside the twenty device slots, and a
    Headphones field that unlocks a measured correction for your model
  - Preset import from a file, the clipboard, a file dropped on the menu bar
    icon, or the AutoEq database (6,000+ headphones), fitted to a target of
    your choice
  - An AI preset studio that designs a preset for your headphones with a
    provider of your choosing, on your own key, only when you press Generate
  - Profiles that pair an output device with a preset
  - Per-app EQ: a second curve for one app, applied on the Mac before the
    audio reaches the 5K
  - Tune: find the EQ you prefer by ear, four ways
  - Stage and Level: a soundstage with crossfeed by band, balance, loudness
    compensation, dynamic bass, your own impulse response and a true-peak
    limiter, plus a listening-level meter with an estimate of the level at
    the ear, applied on the Mac's audio rather than on the 5K
  - A guard for the Bluetooth link: it tells you when an app grabs the
    headset microphone and drops the link to the voice codec, or fixes it
  - Device settings: channel trim, volume limit, DAC filter
  - A diagnostics panel showing every packet exchanged with the device

Either link carries the same commands: USB HID over the vendor interface, or
Bluetooth LE with the same packets tunnelled inside Qualcomm GAIA frames.
The device control never touches the audio path. Stage, Level and stream
quality detection do work on the Mac's audio through a system audio tap;
detection is on by default and the README explains the three switches that
govern the tap.

To start it automatically, add it in System Settings > General > Login Items.


WHAT IT SENDS AND WHERE
-----------------------
Since you are being asked to bypass Gatekeeper on trust, here is every bit of
network and disk activity in the app:

  - It contacts three hosts, each only when you ask: raw.githubusercontent.com
    and autoeq.app when you open the Import pane or name your headphones, to
    fetch the headphone list and the correction you pick; api.github.com when
    you press Check in the About panel, to read the latest release number.
    Nothing is contacted at launch.
  - The AI preset studio adds one more, and only if you use it: the provider
    you picked (api.mistral.ai, api.openai.com, api.anthropic.com or
    openrouter.ai), reached only while you press Generate. What it sends is
    the headphone name you typed, the preset kind, your note, and the public
    AutoEq measurement if there is one. Never your EQ, your presets, your
    devices or any identifier. Your key lives in the macOS Keychain only.
    Before it asks the provider, Generate also reads the public AutoEq list
    and that one measurement file from raw.githubusercontent.com.
  - There is no telemetry, no analytics, no identifiers, no crash reporting.
  - It writes a packet log, ~/Library/Logs/QudelixBar.log, containing device
    packets, firmware version, battery and volume. Because it records raw packet
    hex, it also contains your 5K's own Bluetooth address and any preset names
    you have saved on the device. Its settings live in
    ~/Library/Application Support/QudelixBar/ (the README lists every file).
    Nothing is transmitted, but glance over a file before attaching it to a
    bug report. Bluetooth scanning does not record the names of any other
    devices nearby.
  - It only writes EQ, volume, and preset settings to the 5K — the same
    settings the official app writes. It never touches firmware.


REQUIREMENTS
------------
  - macOS 14 (Sonoma) or later
  - Apple Silicon or Intel (universal binary)
  - Qudelix 5K by USB or Bluetooth. Tested against firmware 3.1.8 and 3.2.7.


TROUBLESHOOTING
---------------
Nothing appears when the device is plugged in:
  Open the Diagnostics section in the popover. It logs every packet. The same
  log is written to ~/Library/Logs/QudelixBar.log.

The device disappears from USB, or the app shows write errors:
  Unplug and replug the 5K. If it persists, please report it with the log.


SUPPORTED DEVICES
-----------------
This app implements the original Qudelix 5K protocol on firmware 3.x. Both the
10-band user EQ and the 20-band mode are supported — it follows whichever mode
the device is in and shows the matching number of bands automatically.

It identifies your device during the connection handshake and, if it finds
anything it does not implement, it says so plainly and writes nothing rather
than silently doing the wrong thing. Cases it will refuse:

  - Qudelix 5K Plus, T71, and Aura Vita — different EQ command set
  - Firmware 2.x — Qudelix changed the command format in firmware 3
  - Firmware 1.x — too old (the official app refuses these too)

In each case, update or switch modes with the official Qudelix app and
reconnect. Nothing is written to the device while it is in a refused state.


KNOWN LIMITS
------------
  - Only the user (headphone) EQ group is exposed, not the speaker group.
  - Preset slots show generic names until you name them.
  - Crossfeed is shown but cannot be changed here.
  - The binary is universal but has only been run on Apple Silicon.
